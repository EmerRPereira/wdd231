DachsIce – Individual Project Site Plan

WDD231 – Web Frontend Development

1. Site Name

DachsIce

The name DachsIce was selected because it is short, memorable, and strongly associated with the identity of an ice cream business. The name allows for playful branding while remaining easy to recognize and suitable for a commercial website.

Optional domain availability: dachsice.com

2. Site Purpose

The purpose of the DachsIce website is to provide an informational and interactive platform for a fictional ice cream shop. The site will present the business, display products with prices and descriptions, and allow users to build and manage an order using dynamic JavaScript features.

The website will also integrate external data through a weather API, displaying current conditions and a three-day forecast on the home page to enhance contextual relevance and demonstrate API usage.

The website will consist of three primary pages: a Home page (index.html), a Products page displaying available ice cream options, and an Order page where users can build and manage their orders.

An HTML order form will be implemented to collect user input and will submit data to a form action page for display, following course standards.

3. Scenarios

  • What ice cream products does DachsIce offer, and how much does each item cost?
  • How can I build an order, customize it with toppings, and see the total price?
  • What is the current weather, and is today a good day to visit the ice cream shop?

4. Color Scheme

  • Pink (#FF6CA8) – Used for headings, primary buttons, and call-to-action elements.
  • Light Blue (#6ECFF6) – Used for accents, secondary buttons, and highlights.
  • White (#FFFFFF) – Used as the main background color to ensure readability and contrast.

This color scheme reflects a fun, fresh, and friendly brand identity appropriate for an ice cream shop.

5. Typography

  • Montserrat – Used for headings and section titles.
  • Poppins – Used for body text, product descriptions, and forms.

This font combination ensures clarity, readability, and a modern appearance, aligning with web accessibility and usability best practices.

7. UX and Performance Considerations

  • Lazy loading will be applied to images below the fold.
  • Explicit width and height attributes will be used to reduce layout shifts.
  • JavaScript will be loaded with the defer attribute.
  • LocalStorage will be used to persist user preferences and cart data.
  • The site will be tested using Lighthouse for performance, accessibility, best practices, and SEO.

Performance metrics such as First Contentful Paint (FCP), Largest Contentful Paint (LCP), and Cumulative Layout Shift (CLS) will be considered during development.

JavaScript will be used to fetch external data, dynamically generate content, manage application state with localStorage, handle user interactions, and implement modal dialogs using ES Modules.
